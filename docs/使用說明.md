# 醫學論文評析工作台 — 使用說明

把一份草稿帶到可投稿狀態的工具組。你是作者，比任何人都懂自己的資料，但離稿件太近，看不到挑剔的審稿人會看到什麼。這套東西負責提供精準的醫學英文、嚴格符合期刊規則，以及共同作者往往不好意思講的誠實批評。

---

## 一、三個部分，各做什麼

| | 是什麼 | 跑在哪 | 誰用 |
|---|---|---|---|
| **skill** | `medical-manuscript-review`，四項服務的作業規範 | Claude Code 讀取 | Claude |
| **本機 runner** | 把四項服務做成可點擊流程的小伺服器 | 你的 Mac | 你 |
| **雲端成果頁** | 唯讀的報告頁，可分享 | claude.ai | 你和共同作者 |

skill 本身不需要 runner 也能用——在 Claude Code 裡上傳檔案、直接講要做什麼就行。runner 只是讓流程可點、可追蹤、有紀錄。

## 二、第一次設定

### 1. 取得檔案

全部都在 `master` 上。

```bash
cd ~/Azygo && git checkout master && git pull
```

> 如果 `git pull` 說 "Already up to date" 但檔案不在，先用 `git branch --show-current`
> 看你在哪條分支。開發分支 `claude/amazing-brahmagupta-qrakhm` 與 master 內容相同，
> 但停在別的分支上就拉不到後續更新。

### 2. 檢查工具

```bash
claude --version
```

```bash
python3 -c "import docx, pptx, openpyxl; print('ok')"
```

```bash
soffice --version
```

缺的話：

```bash
pip install python-docx python-pptx openpyxl
```

```bash
brew install --cask libreoffice && brew install poppler
```

LibreOffice 是用來把圖檔 pptx 轉成圖片的——少了它，Claude 只能讀圖上的文字，看不到圖本身。多數圖表問題（軸沒標、沒寫 n、誤差線沒定義）只有看圖才看得出來，所以這個別省。

### 3. 啟動

```bash
node tools/runner/server.mjs --open
```

瀏覽器會開 `http://127.0.0.1:4178`。只綁本機，不對外。

網址帶 hash 可以直接開到某一篇論文，例如 `http://127.0.0.1:4178/#Noise_TLR9`，
切換論文時網址會跟著變，可以加書籤或貼給自己。

換連接埠：`node tools/runner/server.mjs --port 8766`。
（如果你同時也在跑 Paper Orchestra，兩者要用不同的埠。）

## 三、日常流程

### 1. 新增論文

按「＋ 新論文」，填**放著稿件的資料夾絕對路徑**。本文、supplementary、圖檔 pptx 都放在這個資料夾裡，它就是 Claude Code 的工作目錄。

### 2. 到「材料與設定」

填目標期刊（Service 2 需要）、模型、權限模式。

### 3. 按順序跑

七個階段，A 到 G。**A 與 B 跑完會停下來等你確認**，其餘自動往下。

```
A 剖析 → B 文獻 → C 圖檔 → D 評析 → E 審稿 → F 修改 ⇄ G 把關
                                                  └─ 最多 3 輪 ─┘
```

F→G 是迴圈，這是整套東西的重點：改完之後用**全新的 reviewer** 重審，分數有進步才保留，
沒有就回退。沒有這個閘門，修訂會愈改愈像話但審稿人的異議沒被處理。

每個階段分頁裡的指令可以直接改，改過的版本只用在這次執行。

### 4. 看「執行紀錄」

`[STEP]` 會變成藍色標題帶，工具呼叫顯示成 `Bash ls -la`，點工具輸出可以展開。

**關掉瀏覽器分頁不會中斷流程**，但關掉啟動伺服器的終端機會。

### 5. 看「成果」

列出資料夾裡的檔案。文字檔直接在頁面上讀；Word 與圖檔點了在 Finder 中顯示。

## 四、七個階段

### A 稿件剖析　`需你確認`

擷取 docx/pptx、把圖檔渲染成 PNG、建 manuscript profile。自動標出 placeholder（`XXXX`
之類）、只有標點的空段落、列了但從未被引用的文獻。

會**實際看圖**，不是只讀圖上的文字——多數圖表問題（軸沒標、沒寫 n、誤差線沒定義）只有
看圖才看得出來。這就是為什麼 LibreOffice 不能省。

### B 文獻（PubMed）　`需你確認`

先把文獻表拆成結構化清單，再用 PubMed 逐筆查證。每筆判定為 verified / corrected /
duplicate / retracted / unverified / not_indexed。

- 重複收錄用 **PMID** 比對，不是書目字串——書目殘缺的那筆（通常正是有問題的那筆）字串比不到
- 查不到的標 `[VERIFY]`，**不會自行補上卷期頁碼或 DOI**
- 查到撤稿會立刻在對話裡告訴你，不會只寫進報告
- 也會找你可能漏引的關鍵文獻

PubMed 走 Claude 的 MCP connector，你本機的 Claude Code 要接上同一個 connector。

### C 圖檔稽核

逐張看圖，對照期刊的圖檔規範：panel 標示、字級、解析度、誤差線定義、每組 n、統計標記
是否都在 legend 定義、色盲友善、scale bar、影像完整性、BioRender 授權標註。

不會替你重畫圖。

### D 嚴格評析

先做一致性交叉檢查，再產出 10–20 個 concerns。交叉檢查包含：

- **跨圖列出每組 n**，不可能同時成立的樣本數是審稿人最常抓到的致命傷
- **重算所有能重算的統計**，找出「文字宣稱但從未檢定」的比較
- 檢查 SD / SEM 與圖上分布範圍是否相容
- 把時間窗口、劑量放回該物種的生理尺度
- 檢查硬體設定與分析設定是否相容

### E 三位 reviewer

臨床、方法學／統計、基礎／轉譯，各用獨立 subagent，看不到彼此的意見。除了給人看的報告，
另外產出 `review_v0.json` 供把關迴圈計分。

### F 修改稿件

把 concerns 轉成**追蹤修訂**寫回 docx，你在 Word 裡逐項接受或拒絕。語意不清的地方加
Word 註解問你，不會自己猜。

**不會動的東西**：任何數字、P 值、樣本數、劑量；結論的方向與強度。要改變主張強度屬於
concern，要你同意，不是語言編修。

需要新實驗或重新分析的 concern **不會在稿件上動手**，只寫進回覆草稿。

對不上的修訂（稿件已經改過、原文找不到了）會列在紀錄裡，不會默默跳過。

### G 把關迴圈

用**全新的 reviewer subagent** 重審改後稿件——它看不到修改理由，也看不到前一輪意見。
然後比分：

| 情況 | 結果 |
|---|---|
| 整體建議上升 | 接受，繼續下一輪 |
| 整體建議下降 | 回退，停止 |
| 持平、五軸淨增益 | 接受，繼續 |
| 持平、五軸淨損失 | 回退，停止 |

最多 3 輪。回退會**真的回退**，回到上一版，並說明哪一輪被回退、為什麼。

這一段改寫自 [google-research/paper-orchestra](https://github.com/google-research/paper-orchestra)
（Song et al., 2026, Apache-2.0），原版是從實驗紀錄寫新論文，這裡換成審閱既有稿件、
文獻來源換 PubMed、檔案格式換 docx/pptx。

## 五、權限模式

headless 的 `claude -p` **不會跳出權限視窗**，所以這項決定了流程遇到未授權動作時的行為。

| 模式 | 行為 |
|---|---|
| `acceptEdits`（預設） | 自動接受檔案編輯，其餘仍需授權——未授權的會停住 |
| `dontAsk` | 不詢問，未授權的動作直接略過（流程繼續，但可能少做事） |
| `bypassPermissions` | 略過所有權限檢查 |
| `plan` | 只規劃不執行 |

想要全自動跑完通常得用 `bypassPermissions`，但那會讓流程能刪檔案、對外連線、執行任意指令而不問你。只在你信任那個資料夾內容時使用——稿件是你自己的，但如果資料夾裡有別人給的檔案，它們的內容會進到 Claude 的 context。

**建議**：第一次用 `plan` 跑一次，看它打算做什麼，再決定放寬到哪裡。

## 六、檔案放哪

| 東西 | 位置 |
|---|---|
| 流程產出的報告與稿件 | **你的論文資料夾** |
| 論文清單 | `tools/runner/.runner-data/projects.json` |
| 執行紀錄 | `tools/runner/.runner-data/runs/run-<時間>-<服務>.jsonl` |
| 每次執行的狀態、花費 | 同上，`.meta.json` |

執行紀錄是原始的 stream-json，一行一個事件，想看就直接 `cat`。伺服器重開後舊紀錄還在。

## 七、常見問題

**`Cannot find module '.../server.mjs'`**
檔案沒拉下來，通常是停在別的分支上。`git checkout master && git pull`，
再用 `ls tools/runner/server.mjs` 確認。

**按了沒反應、紀錄是空的**
看啟動伺服器那個終端機。`claude` 不在 PATH 時會出現 `spawn claude ENOENT`。

**流程卡住不動**
多半是權限。到執行紀錄看最後一個工具呼叫是什麼，再調整權限模式。

**圖檔沒被真的看過**
確認 LibreOffice 裝了。左下角「環境」會顯示實際檢查結果。

**期刊網站抓不到**
Claude Code 在雲端時每個期刊網域要個別開放；在你自己電腦上跑就沒這個限制。真的抓不到就把 guidelines 貼給它，或上傳 PDF。

**想中止**
按橫幅上的「停止」。送 SIGTERM，8 秒後沒結束就 SIGKILL。

## 八、關於產出的使用

### AI 使用聲明

多數期刊要求揭露寫作過程使用 AI 的情形。這篇稿件原本已聲明使用 ChatGPT；若這次修改也用了 AI 協助，請依目標期刊規定更新那段聲明。這是作者的責任，工具不會替你判斷。

### 報告是給你判斷用的，不是結論

三位 reviewer 是模擬的，不是真的審稿意見。它們的價值在於讓你在真正投稿前先把答辯演練一遍。評析裡的每一條都要你自己回去核對原始資料——工具重算的是稿件上印出來的數字，看不到你的原始檔案。

### 分享給共同作者

雲端成果頁（Artifact）是唯讀的報告頁，含 49 條意見與勾選清單，共同作者開連結就能讀、能勾。預設是私人的，要從頁面的 Share 選單分享出去。

本機 runner 不能分享——它跑在你電腦上，能讀寫你的檔案。

```
請用 medical-manuscript-review skill 評析我上傳的稿件，

```
